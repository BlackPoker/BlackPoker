## 初期の問題と設計の経緯

第9.1版系列のコアフローは、ステージが空でもパスでき、全員がパスを繰り返すとターンが進まない構造でした。また、直接リクエスト時にパス記録をリセットする一方、ステージの1件解決後にはリセットがなく、以前の全員パスを次のリクエストにも使ってしまう経路がありました。

[Issue本文](https://github.com/BlackPoker/BlackPoker/issues/642)の初期案はパス記録方式を維持し、空ステージでのパス禁止とチャンス調整を導入するものでした。その後のローカル履歴では、次の順序を確認しました。

1. `657ed22c2`：パス記録を維持し、空ステージでのパス禁止と共通のチャンス調整を導入。
2. `79b565790`：パス記録を廃止し、フォーカス方式を導入。
3. `ec7a6ea3f`：処理を [1]～[14] に整理し、不要なステージ存在判定を削除。誘発チェックの子番号も更新。
4. `47bd4b210`：説明文を補正。過去のCodex状態遷移レビューの対象HEAD。
5. `9c5ed6c21`：全プレイヤーを経由する循環順序の前提、誘発チェック内でのチャンス・フォーカス非更新を明記。通常誘発ループの出口をNoへ修正。

方式の比較は次のとおりです。パス回数方式と「最後にリクエストしたプレイヤー」案の詳しい議論日時・原文は今回取得できていないため、比較の整理として記載します。採用コミットが確認できた方式と、検討案を区別しています。

| 方式 | 管理する情報 | 注意点 |
|---|---|---|
| パス記録方式 | パスしたプレイヤーの集合 | 直接リクエスト時と、1件解決後の応答開始時のリセットが必要 |
| パス回数方式 | 連続パス数 | 固定巡回なら人数との比較が可能だが、回数とリセット契機の管理が必要 |
| 最後にリクエストしたプレイヤーを記録する案 | 巡回の基準になるプレイヤー | ゲーム開始時やステージ解決後は「最後のリクエスト者」とは限らないため、名称・設定条件を一般化する必要がある |
| フォーカス方式(最終案) | 全員パス判定の基準となるプレイヤー1人 | 開始・直接リクエスト後・チャンス調整時に設定し、固定巡回の終端を判定する |

誘発チェックはリクエストの分類、即時解決、ステージ追加を担当し、フォーカス管理は外側のコアフローで行います。誘発の処理対象プレイヤーを変えることは、チャンスやフォーカスを移すことではありません。

## 最終仕様

| 処理 | チャンスとフォーカスの扱い |
|---|---|
| [1] ゲーム開始 | 最初のターンプレイヤーにフォーカスを設定 |
| [2] チャンス調整 | プレイヤーがチャンスを持たない場合、またはステージが空の場合に、両方を現在のターンプレイヤーに設定。それ以外は両方維持 |
| [3] パス選択 | ステージが非空の場合だけ可能。空ならエンドなどのアクションをリクエスト |
| [10] 直接リクエストの処理後 | 通常・即時の両方で、誘発チェック後にリクエストしたプレイヤーへフォーカスを設定 |
| [11] 全員パス判定 | パスするプレイヤーの次の移動先がフォーカスなら成立。そうでなければ [14] で次のプレイヤーへチャンス移動 |
| [12]～[13] ステージ解決 | ルールシステムへチャンスを移し、最後の1件を解決。勝敗が決まらなければ誘発チェック後に [2] へ戻る |
| 誘発チェック内部 | チャンスとフォーカスを変更しない |

フォーカスはプレイヤーを示し、ルールシステムを示しません。ターン・チャンスとは独立した情報です。

全員パスの判定は、チャンスが固定された循環順序で全プレイヤーを1回ずつ経由することを前提とします。巡回中の順序変更や参加者変更は追加ルールを要し、今回の仕様には含めません。

通常リクエストを積んだ直後も本人がチャンスを持ち、パスして相手に渡します。1件解決後は現在のターンプレイヤーから新たな応答を開始します。これは、旧図のパス記録リセット漏れの解消を含む変更です。

具体例(追加の誘発でステージを変えない場合)：

- P1アタック → P1パス → P2サーチ(即時) → フォーカス=P2 → P2パス → P1が応答可能。P1もパスするとアタックを解決。
- ステージを下から[A, B]とする → 全員パス → Bだけ解決 → チャンス=フォーカス=現在のターンプレイヤー → 全員に改めて応答機会 → 全員パスでAを解決。
- エンド解決でターン移動 → 誘発チェック → 新しいターンプレイヤーへチャンスとフォーカスを設定。誘発したドローにも応答可能。
- 休戦や罠カウンターで最後のリクエストを除去し、誘発チェック後も空なら、ターンプレイヤーに戻る。非ターンプレイヤーの連続行動に影響する意図した変更。

旧 [14] のステージ存在判定は、パス入口で非空を保証し、そこから解決までにステージを変更しないため削除できます。これは全ての無限ループを防ぐ仕様ではなく、アクションの繰り返しや無限誘発は別問題です。
