### 2.2 高さ削減方式の比較：案1（別列維持＋5段階削減：採用） vs 案2（左右2カラム：不採用・参考比較）

| 比較軸 | 【採用案】案1：兵士・防壁の別列（縦並び）を維持＋5段階高さ削減 | 【参考案・実装しない】案2：兵士列と防壁列を左右2カラム化 |
| :--- | :--- | :--- |
| **実カード配置との視覚的一致** | **◎ 完全一致**<br>実際のBlackPokerのテーブル配置（前衛＝兵士列、後衛／ライフ側＝防壁列）と上下位置関係が一致し、直感的に盤面を把握できる。 | **✕ 不一致**<br>兵士と防壁が横に並ぶため、どちらが前衛・後衛かの直感的対応が崩れる。 |
| **段階1: ヘッダーとZoneStrip統合** | **`-64px`** (`32px × 2` 削減：サマリーヘッダー右側にFOG・墓地・PACK・RAREを統合) | `-64px` |
| **段階2: 不要な余白・外出しラベル削減** | **`-108px`** (`FIELD` / `兵士 (N体)` / `防壁 (N体)` / `HAND` の独立ラベル行を枠内インラインバッジ化し余白を圧縮) | `-108px` |
| **段階3: DRIVE回転余白 (`my-3`) と相手手札高の改善** | **`-132px`** (`UnitCard` のDRIVE時 `my-3` [24px] を `my-0.5` [4px] に縮小し、相手の裏向き手札をコンパクト化) | `-132px` |
| **段階4: STAGEのコンパクト化** | **`-32px`〜`-65px`** (空時は1行スリムバー `34px`、積載時は `max-h-28 overflow-y-auto`) | `-32px`〜`-65px` |
| **段階5: 各ペイン・フィールドの独立スクロール** | `1366×768` 等の低背画面で4列フル展開された場合でも、左ペイン（および各フィールド）が独立スクロールして右ペインの操作を妨げない。 | 左右2カラム化によりさらに `-190px` 削減されるが、横幅が半分になり横スクロールが頻発する。 |
| **削減後の左ペイン総高** | **4列フル展開時: `864px` (`-336px` 削減)**<br>**通常3列展開時: `760px` (`-440px` 削減)** | 4列フル展開時: `674px` (`-526px` 削減) |
| **解像度別適合性** | `1920×1080` (`<=1080px`): **縦スクロールなし (0px)**<br>`1440×900` (`<=900px`): **縦スクロールなし (0px)**<br>`1366×768` (`<=768px`): 通常3列時は縦スクロールなし、4列時は左ペイン独立スクロールで完全対応 | 全解像度で縦は収まるが、1プレイヤーに兵士4体＋防壁3体が並ぶと横幅が溢れる |

👉 **結論:** 案1（**兵士・防壁の別列配置を維持した5段階高さ削減**）により、実カード配置との視覚的一致を100%守りながら **`336px〜440px` の高さ削減**を達成でき、`1920×1080` および `1440×900` でページ縦スクロールゼロ、`1366×768` でも独立ペインスクロールによる快適な操作が実現できる。よってPhase 2では案1を実装し、2カラム案は採用しない。
