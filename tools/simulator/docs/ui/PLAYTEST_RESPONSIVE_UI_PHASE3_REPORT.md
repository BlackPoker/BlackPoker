## 2. スマートフォン（`390×844` / `360×800`）の回帰検証結果

スマホ（`<768px`）の既存レイアウト（`max-w-md flex-col` の `MobileDecisionDock` およびフル幅 `MobileBottomSheet`）には不要な変更を加えず、以下の全項目で回帰がないことを実ブラウザーおよびテストスイートで確認しました。

- **Human vs AI / Human vs Human (Pass-and-Play)**: 端末受け渡し時の秘密情報遮蔽オーバーレイ（`PassAndPlayOverlay`）と相手手札・伏せ防壁の秘匿境界が100%維持されていることを確認。
- **`ACTION_REQUEST` / `EFFECT_RESOLUTION` / `ZONE_TOP_SELECTION`**:
  - 通常アクション選択（防壁設置、兵士召喚、アタック、アップ等）
  - `EFFECT_RESOLUTION` 発生時の BottomSheet 自動展開（アタッカー指定・ブロッカー割当て）
  - ダメージ判定解決後の `ZONE_TOP_SELECTION`（「Player B の墓地TOPを選択」で被ダメージ5枚 `♣4, ♦7, ♥7, ♣8, ♦8` から選択し `墓地 7 TOP: ♣4` へ更新）
- **`BlockAssignmentEditor` のスマホ表示改善**:
  - 従来 `BlockAssignmentEditor` 末尾にあった重複 `SHORTCUT:` 行を除去し、「現在の割当て」サマリーをスクロール領域内へ移動して「この割当てで決定」ボタンのみを `sticky bottom-0` 化したことで、`390×844` / `360×800` の BottomSheet 標準（half）モードでもアタッカー・ブロッカー選択肢の可視領域を約 `113px` 拡大。
- **Undo（「戻る」/「1つ戻る」）操作**: デスクトップ・タブレット・スマホのすべてで直前の判断ステップへ正確に巻き戻ることを確認。

## 5. Phase 4（文字サイズ変更と設定保存）実装時に注意すべき残課題

1. **小画面・低背画面での文字サイズ拡大（115% / 130% / 150%）時の折り返し許容設計**:
   - `1024×768`（左ペイン幅 `576px`）や `360×800` では、標準（100%）サイズでバッジやボタンがちょうど1行〜2行に収まっているため、Phase 4 で 130%・150% に拡大した際は `flex-wrap` と `min-h`（固定 `h-*` ではなく `min-h-*`）を維持し、テキストのクリップ（文字切れ）を起こさずに折り返し＋ペイン内スクロールで吸収する必要がある。
2. **`DecisionPanel` および `MobileBottomSheet` 内の固定ヘッダー・フッター高さの比率**:
   - 文字サイズ 130%・150% 時に `decision-panel-header` と `decision-panel-sticky-footer` の高さが増えた際にも、中央の `decision-panel-scroll-body` が十分な可視高さを確保できるよう、`MobileBottomSheet` 側で拡大モード（`expanded`: `85vh` / `88dvh`）への切り替え導線（`⤢` ボタン）を引き続き維持することが有効である。
