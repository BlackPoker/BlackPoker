## 1. エグゼクティブサマリー

### 1.1 調査の背景
人間がブラウザ上のプレイテストにおいて Gen 9 v7.2b および v7.3b と対戦した際、「双方とも強さを感じられず、**アタックがブロックされない現象**」が報告された。  
本調査は、この実戦フィードバックを最優先事項として受け止め、Core の意思決定要求生成、ブロッカー候補抽出、Gen 8 DNA ベーススコア、戦術補正（t14, t15, t16）、通常列挙とストリーミング列挙の一致性、および GameSession 統合環境での実挙動を多角的に診断・特定したものである。

### 1.2 診断結果の総括（結論）
1. **Core および DecisionRequest 生成の真正性:**  
   - Core は正常に動作しており、攻撃側がアタッカーを指定してアタックを解決した際、防御側 AI に `action.block` の意思決定要求（`selectionType: "unitAssignment"`）が確実に生成される。
   - チャージ状態の兵士および防壁は、正しくブロッカー候補として抽出される。
2. **AI の評価ロジック単独の挙動:**  
   - 単一のブロック局面において、AI は「ブロックしない手（スルー）」を好んでいるのではなく、**むしろ「何かしらブロックする手」を強力に選好している**。
   - 有利ブロック、致死回避ブロック、防壁撃破ブロック、複数兵士合体ブロックのいずれも確実にブロック手を選択する。
3. **実戦で「アタックがブロックされない」現象が発生した真因（3重の複合要因）:**
   - **要因 A（自滅ブロックによるブロッカー枯渇）:**  
     Gen 8 Champion DNA は「ブロック手（EffectSelection）」に対して約 `+0.09` の強いベーススコア加点を持っている。一方、不利ブロックに対する戦術ペナルティは `-0.05`（`0.2 * -0.25`）しかないため、**自軍兵士が一方的に犬死する不利ブロックであってもブロックを選択してしまう**。その結果、序盤〜中盤に兵士を無駄死にさせてブロッカーが全滅し、以降のアタックに対してブロックできるユニットが盤面に残らない。
   - **要因 B（AI の全軍アタックによるドライブ状態化）:**  
     AI はアタック可能兵士を積極的にアタックに使用するため、自軍兵士が全員「ドライブ（疲労）状態」になりやすい。ドライブ状態の兵士はルール上ブロック不可のため候補数 0 体となり、Core の仕様（`candidates.length === 0`）により自動スルー（0体ブロック）として即時解決され、人間側からは「兵士がいるのにブロックしてこない」と認識される。
   - **要因 C（UI/UX 操作上のトラップ）:**  
     人間がアタック宣言時、アタッカー選択（`selectUnits`）の先頭選択肢は「なし (0体)」である。もしアタッカーが選択されないまま決定された場合、アタック自体がアタッカー 0 体で即時終了するため、`hasAttacker: false` となり `action.block` の DecisionRequest 自体が一切発生しない。

## 3. シナリオ別 詳細診断データ

### シナリオ 1: 有利なブロック (自軍サイズ6 vs 敵サイズ3, ライフ15)
- **盤面設定:** 敵アタッカー: ♠3 (size 3) / 自軍ブロッカー: ♠6 (size 6)
- **期待行動:** BLOCK (一方的撃破かつ自軍生存)
- **結果:** **PASS (didBlock: true)**
  - パターン 0 (ブロックなし): Base = 0.0693, Tactical = 0, **Final = 0.0693**
  - パターン 1 (自軍6でブロック): Base = 0.1323, Tactical = +0.2000 (`t14_favorable_block`), **Final = 0.3323**
  - AI 選択: パターン 1 (有利ブロック選択, 差分: +0.2630)

### シナリオ 2: 不利なブロック (自軍サイズ2 vs 敵サイズ5, ライフ15) ★重要発見
- **盤面設定:** 敵アタッカー: ♠5 (size 5) / 自軍ブロッカー: ♠2 (size 2), 安全圏ライフ15
- **合理的な期待行動:** NO_BLOCK (自滅犬死を回避しスルー)
- **結果:** **FAIL (didBlock: true — 犬死ブロックを選択してしまう)**
  - パターン 0 (ブロックなし): Base = 0.0459, Tactical = 0, **Final = 0.0459**
  - パターン 1 (自軍2でブロック): Base = 0.1378, Tactical = -0.0500 (`t14_unfavorable_block`), **Final = 0.0878**
  - **分析:** Gen 8 DNA がブロック手に対して約 `+0.09` のバイアスを持つため、ペナルティ `-0.05` を引いても `0.0878 > 0.0459` となり、**無駄死にブロックを選んでしまう**。

## 4. 人間の実戦フィードバック「アタックがブロックされない」根本原因の究明

人間のプレイテストにおいて「なぜアタックがブロックされなかったのか」について、診断結果に基づき以下の3つの要因を切り分けた：

### 要因 1: AI の不利ブロック過剰によるブロッカーの早期全滅（AI戦術の欠陥）
- 診断シナリオ 2 が示すように、AI は「自軍2 vs 敵5」のような、安全圏ライフ（ライフ15）であっても無駄死にするブロックを行ってしまう。
- 実戦で人間がサイズ 5〜8 の主力兵士でアタックしてきた際、AI は手持ちの小兵士（サイズ 2〜4）で無謀にブロックして犬死させ、早期に自陣の兵士を失ってしまう。
- その結果、盤面にブロッカーが残らなくなり、以降のアタックに対してブロックしたくてもできなくなっていた。

### 要因 2: AI の「全軍アタック志向」による自陣の無防備化（盤面リソース管理の欠陥）
- Gen 8 DNA および Gen 9 の攻撃戦術は、アタック可能兵士を積極的にアタックへ投入する。
- AI がターンで全兵士でアタックを行うと、全兵士が「ドライブ（疲労）状態」となり、相手のターンにブロック可能なユニットが 0 体となる。
- 人間が次のターンにアタックした際、AI の場には兵士が存在するにもかかわらず全員ドライブ状態であるため、Core はブロック候補 0 体として自動でスルー（0体ブロック）を処理する。
- 人間側から見ると、「AI の場に兵士がいるのになぜか全くブロックしてこない」という不自然なスルー現象に見える。

### 要因 3: UI/UX におけるアタッカー選択の操作不整合（UI側の可能性）
- `action.attack` の解決時、アタッカー選択ダイアログで先頭に「なし (0体)」が配置されている。
- もし人間プレイヤーが盤面タップやリスト選択を完了せずに「決定」した場合、アタッカー 0 体でアタックが終了し、`action.block` の DecisionRequest 自体が発生しない。

## 5. 修正の要否と推奨対策

### 5.1 修正の要否
**要修正（推奨）**  
Core ルールや YAML DSL の不具合ではなく、**AI の戦術重みバランス（Gen 8 DNA のブロックバイアスに対する戦術補正の不足）**、および **盤面兵士のリソース運用** に明確な改善ポイントが存在する。  
ただし、今回の作業指示に従い、勝手なコード変更は行わず、以下に対策案を提示して停止する。

### 5.2 推奨対策案

#### 対策 1: 不利ブロックペナルティの重み強化 (P0 推奨)
- **現状:** 不利ブロックペナルティは最大でも `-0.05`（`0.2 * -0.25`）であり、Gen 8 DNA のブロック加点（約 `+0.09`）を打ち消せない。
- **改善案:**  
  非致死・安全圏ライフ（`selfLife > 8`）での不利ブロックペナルティ重みを強化する：
  ```ts
  // 安全圏での犬死ブロックに対して -0.20〜-0.30 の強いペナルティを付与
  const unitLossPenalty = selfLife > 8 && blockerTotalSize < atkSize
    ? 1.0 * blockerUnitIds.length // final 換算で -0.20
    : 0.25 * blockerUnitIds.length;
  ```
  これにより、安全圏では「ブロックなし（スルー）」が Final スコアで確実に上回り、合理的なスルー判断ができるようになる。

#### 対策 2: ブロッカー温存戦術の導入 (P1 推奨)
- 敵陣に高サイズ兵士が存在する場合、自軍の全兵士をアタックに投入せず、防御用のチャージ兵士を1体残す「ブロッカー温存ボーナス」をアタック評価に加える。
- これにより、相手ターンに自陣が無防備（全員ドライブ状態）になる現象を防ぎ、相手のアタックをブロックで受ける構えを維持できる。

#### 対策 3: アタッカー選択 UI における 0 体アタックの明示と確認（P2 次回 UI 課題）
- **ルール上の注意:** BlackPoker 公式ルールにおいて、アタック宣言後の「アタッカー 0 体指定（空集合アタック）」は合法手である。したがって、決定ボタンを非活性化・無効化することは公式ルール違反となるため行ってはならない。
- **UI 改善案:** アタッカーが 1 体も選択されていない状態で決定ボタンを押す場合、「アタッカー 0 体でアタックを終了しますか？（相手へのブロック判定は発生しません）」等の視覚的明示や確認ワンステップを挟むことで、プレイヤーの誤操作による意図しない 0 体アタック終了を防止する（次回 UI 改修課題として記録）。
