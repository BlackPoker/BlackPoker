## 現行ルール確認の要点

- アタックは1ターン1回、チャージ状態の攻撃キャラクター。出たターンは速攻がなければ攻撃不可。
- 兵士ブロックはチャージ状態で複数可。兵士同士は数字（複数なら合計）を比べ、同数なら両方墓地。
- 防壁は公開後、Jokerまたは防壁の数字が攻撃側カードに含まれると攻撃側を墓地。その後、防壁を墓地。大小比較ではない。
- 防壁設置L・裏向きチャージ・1ターン1回。開始時プリセットとは区別。
- 一般兵BL / 2〜10、英雄BBL / J〜K、エースL / A。装備BL / 同スート、サイズ・速攻はcharList参照。
- 基礎魔法はD、クイック、通常。アップは加算、ダウンは減算し0以下なら墓地。ツイストは向き変更。カウンターはキーカード数と数字の条件あり。
- 投擲は♠＋♣、ダメージは♠の数字。防壁破壊は♥＋♢。Entry16の例を使うが、ここでは操作実装済としない。
- エンドは手札上限・フォグ整理・ターン移動。チャージは即時、ドローは通常。ドローは2枚、ライフ2以下なら1枚（選択式ではない）。
- 世代交代はJoker/A/J/Q/Kが自分の場から墓地へ移るたび。サーチはJoker、公開→手札→シャッフル。Entry16へJokerを混ぜない。
- 通常/即時はspeed。旧「通常効果/即時効果」「速攻魔法」「召喚酔い」、旧ドローや旧誘発処理は導入しない。

## データと互換性の設計

`learning-path.json` に分類・Lesson・説明・参照・担当actionIdを集約する。既存entry16のsceneはそれぞれの最初のbeforeを教材fixtureとして利用し、Lesson間の盤面継続は要求しない。各scene内の操作順・before/afterの検証は維持。防壁ブロックは独立scenarioとする。

旧30操作の保存インデックス・maxReached・先攻は変更しない。別キーのLesson保存で現在Lessonと完了集合を持つ。旧保存からsceneへ復帰し、復習では最高到達を減らさない。準備中は完了不可。動画は任意、実在URLの提供がないため教材へ架空のURLは登録しない。

旧資料から採るのは、依頼文で示された「1画面1概念」「具体例→操作→抽象的な説明」「比較」「流れ」。今回未提供の動画やPDFの内容を推測して転載しない。

## 後段Lessonの設計境界

- チャンスはアップ・ダウン・ツイスト・カウンターの具体的な操作後に配置。将来の盤面にはSTAGEを設け、宣言したカードと解決待ちのリクエストを区別する。Aのアップ→Bの対応（ダウンまたはパス）→全員パス→一番上を解決、を現行のチャンス遷移に沿って操作させる。旧動画のパス列を固定で移植しない。
- 現行 `source/common/common-action.rst` を確認。通常はステージを経由し割り込み機会があり、即時はステージを使わない。解決には効果・ステージからの除去・キーカードの墓地移動が含まれ、場などへ出したカードには例外がある。
- 誘発は3段階の具体例（アタック→ブロック、ブロック→判定、エンド→チャージ→ドロー）から名前を教え、世代交代、同時誘発へ進む。`source/core/triggerflow.puml` と `triggerflow_detail.puml` の即時/通常×メイン/クイック、プレイヤー毎の処理、後発メイン誘発の破棄を確認。AP/NAPだけの単純な順序表に置き換えない。
- 現エンジンにはステージ・フォグ・サイズ修正・装備ユニット・条件付き探索がない。これらを必要とするLessonは、今回、見た目だけで処理済みにせず準備中とする。Jokerサーチも独立fixtureと公開・シャッフルの操作が実装されるまで準備中。

## 今回の実装結果

公開済みは戦闘、ブロックなし、兵士召喚、防壁設置とターン交代、エンドとチャージ・ドロー、防壁ブロック、実物準備の7操作Lessonと、読み方の1ミニ解説。これに任意の盤面復習を加える。その他20Lessonは準備中。
主担当アクションの割当は19/19だが、操作体験として実装済みなのは8アクション（attack / block / damageJudge / setBulwark / summonsSoldier / end / charge / draw）。この2種類のcoverageを混同しない。
旧6sceneの正解操作・タップ→タップ・PCドラッグ・キーボードは変更せず再利用。hookには表裏変更時の成功文だけを追加した。
