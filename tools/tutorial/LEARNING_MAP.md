基準: `05577b2b9d7c104e6104aef9f820d158722f4c8b`。開始時にoriginをfetchし、local / remoteの一致を確認。

3つの戦闘アクションの主担当は最初に体験するunblocked-attackへ移し、兵士・防壁のブロックはreviewとして扱う。

## 現行ルール確認の要点

- アタックは1ターン1回、チャージ状態の攻撃キャラクター。出たターンは速攻がなければ攻撃不可。
- ドライブ状態のキャラクターはブロッカーに指定できない（防壁も含む）。兵士ブロックは複数可。兵士同士は数字（複数なら合計）を比べ、同数なら両方墓地。
- 防壁fixtureは元盤面のdriveを引き継がず、down / chargeを明示する。指定ではドライブせず、damageJudgeで公開して数字一致を判定。検証はdriveのブロッカーを拒否する。
- 防壁は公開後、Jokerまたは防壁の数字が攻撃側カードに含まれると攻撃側を墓地。その後、防壁を墓地。大小比較ではない。
- 防壁設置L・裏向きチャージ・1ターン1回。開始時プリセットとは区別。
- 一般兵BL / 2〜10、英雄BBL / J〜K、エースL / A。装備BL / 同スート、サイズ・速攻はcharList参照。
- 基礎魔法はD、クイック、通常。アップは加算、ダウンは減算し0以下なら墓地。ツイストは向き変更。カウンターはキーカード数と数字の条件あり。
- 投擲は♠＋♣、ダメージは♠の数字。防壁破壊は♥＋♦。Entry16の例を使うが、ここでは操作実装済としない。
- エンドは手札上限・フォグ整理・ターン移動。チャージは即時、ドローは通常。ドローは2枚、ライフ2以下なら1枚（選択式ではない）。
- 世代交代はJoker/A/J/Q/Kが自分の場から墓地へ移るたび。サーチはJoker、公開→手札→シャッフル。Entry16へJokerを混ぜない。
- 通常/即時はspeed。旧「通常効果/即時効果」「速攻魔法」「召喚酔い」、旧ドローや旧誘発処理は導入しない。

## データと互換性の設計

`learning-path.json` に分類・Lesson・説明・参照・担当actionIdを集約する。既存entry16のsceneはそれぞれの最初のbeforeを教材fixtureとして利用し、Lesson間の盤面継続は要求しない。各scene内の操作順・before/afterの検証は維持。防壁ブロックは独立scenarioとする。

旧30操作の保存インデックス・maxReached・先攻は変更しない。旧Lessonキーを非破壊で読取り、新bookキーへ最後のSection・解放済み・完了IDを移行する。再読込時はhashまたは最後のSectionへ戻し、完了した盤面は最終状態、未完了はその盤面の先頭から復習する。復習で最高到達や完了を減らさない。準備中は完了不可。動画は任意で、架空の教材URLは登録しない。

旧資料から採るのは、依頼文で示された「1テーマ1Section」「具体例→操作→抽象的な説明」「比較」「流れ」。今回未提供の動画やPDFの内容を推測して転載しない。

## 後段Lessonの設計境界

- チャンスはアップ・ダウン・ツイスト・カウンターの具体的な操作後に配置。将来の盤面にはSTAGEを設け、宣言したカードと解決待ちのリクエストを区別する。Aのアップ→Bの対応（ダウンまたはパス）→全員パス→一番上を解決、を現行のチャンス遷移に沿って操作させる。旧動画のパス列を固定で移植しない。
- 現行 `source/common/common-action.rst` を確認。通常はステージを経由し割り込み機会があり、即時はステージを使わない。解決には効果・ステージからの除去・キーカードの墓地移動が含まれ、場などへ出したカードには例外がある。
- 誘発は3段階の具体例（アタック→ブロック、ブロック→判定、エンド→チャージ→ドロー）から名前を教え、世代交代、同時誘発へ進む。`source/core/triggerflow.puml` と `triggerflow_detail.puml` の即時/通常×メイン/クイック、プレイヤー毎の処理、後発メイン誘発の破棄を確認。AP/NAPだけの単純な順序表に置き換えない。
- 現エンジンにはステージ・フォグ・サイズ修正・装備ユニット・条件付き探索がない。これらを必要とするLessonは、今回、見た目だけで処理済みにせず準備中とする。Jokerサーチも独立fixtureと公開・シャッフルの操作が実装されるまで準備中。

## 今回の実装結果

Lesson metadataは29項目（公開9・準備中20）を保持。本文は導入3Sectionと向き1Sectionを加え、公開13Sectionで進捗を数える。未到達は本文に出さず、目次から直接開くこともできる。旧30操作のJSONは進捗互換用に維持し、新book fixtureを生成して使用する。

|固定教材|micro step数|ユーザーが行うこと|相手側の表示|
|---|---:|---|---|
|盤面確認|4（静的）|置き場の探索は任意|なし|
|守らない攻撃|3|Aの♠2をアタック|ブロックなし、ライフ2枚を順次墓地へ|
|兵士ブロック|2|Aの♥7→相手の♣6を指定|Bの♣6を墓地へ|
|防壁ブロック|4|Aの防壁で指定・公開・墓地へ|Bの♣6を墓地へ|

`userPlayer: A` と `automatic` を実行時検証する。手動のactor・operationのplayerがBならエラー。Bのカードを対象に指定する操作は許可する。interaction.mjsにLesson ID固有の分岐は追加しない。

主担当アクションの割当は現行Liteの19/19。教材で体験・表示済みは8アクション（attack / block / damageJudge / setBulwark / summonsSoldier / end / charge / draw）。相手側の処理は自動表示であり、すべてをユーザーが直接操作するという意味ではない。未完成の魔法・複数ブロック・誘発教材などは今回増やしていない。

カードは共通部品でrank＋suitを1組だけ表示。♥♦を赤、♠♣を黒にし、背面はBPだけ。正規YAML・生成カタログは変更せず、UI用カタログで記号を正規化する。各Sectionのboard内へ矢印・dropの範囲を閉じ、複数盤面を保持しても干渉させない。
